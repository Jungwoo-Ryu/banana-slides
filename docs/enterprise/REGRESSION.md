# Sol.A 버전업 회귀 검증 (2026-11-01)

기준 버전은 `72c71e0`(Azure 전용 전환 전)과 `2ed3760`(Sol.A·Azure·TTS 적용 후)입니다. 사용자 데이터와 분리한 SQLite·업로드 폴더에서 검사했습니다.

브라우저는 `start_local.py`가 띄운 실제 Waitress 백엔드와 Vite 프런트엔드에 연결했습니다. 모델 부분은 localhost의 Azure OpenAI 프로토콜 테스트 서버로 교체했습니다. 따라서 SDK 호출·SSE·작업 실행·DB 저장·파일 생성은 실제 경로를 거치지만, 사내 모델의 응답 품질은 검증하지 않습니다.

## 브라우저에서 확인한 흐름

1. 한국어 설정 저장·새로고침, 비밀키 입력 UI 부재.
2. 참고 TXT 업로드·로컬 파싱·삭제.
3. 빈 프로젝트·페이지 생성 → 영역 드래그·첨부 → 수정 프롬프트 제출 실패 시 입력 유지 → PPTX 브라우저 다운로드. 이 시나리오의 수정 API는 오류 응답 대역을 사용합니다.
4. Sol.A 이름·태양 로고, 디자인 시스템 프롬프트 저장·새 프로젝트 기본값 적용.
5. 대본 수정 직후 영상 내보내기 → 마지막 수정본 저장 → Azure SDK TTS 요청 → FFmpeg MP4 생성 → 브라우저 다운로드. FFprobe로 음성·영상 스트림을 확인합니다.
6. 개요 SSE → 설명 SSE·페이지별 TTS 대본 생성 → 디자인 프롬프트를 포함한 이미지 생성 → 이미지 수정 성공 → 이전 이미지 버전 복원 → PPTX·PDF·이미지 ZIP 다운로드. 파일을 다시 열어 페이지 수·ZIP 무결성을 검사합니다. 대본이 이미지 프롬프트에 섞이지 않는지도 검사합니다.
7. 3페이지 PDF 템플릿 업로드 → 분할·비전 분석 → 특정 슬라이드에 수동 연결 → 이미지 생성 → 미리보기.

## 발견하고 수정한 문제

- **실제 WSGI 서버에서 SSE가 실패함:** 두 스트리밍 API가 `Connection: keep-alive`를 반환해 Waitress에서 PEP 3333 위반 오류가 발생했습니다. 연결 관리는 서버에 맡기도록 해당 헤더를 제거했습니다. 두 생성 경로를 실제 서버 브라우저 테스트에 추가했습니다. 이 헤더는 `72c71e0`에도 있었습니다.
- **한국어 Markdown 내보내기 후 다시 가져오기에서 내용이 유실됨:** 페이지·섹션 표기 및 여러 단어로 된 필드명을 인식하고, 여러 줄 필드·TTS 대본의 경계를 보존하도록 수정했습니다. 한국어·영어 왕복 및 이전 형식 호환 테스트를 추가했습니다.
- **저장 버튼이 1.5초 뒤 서버 재조회로 완료를 가정함:** 실제 저장 요청 완료를 기다리도록 수정했습니다. 저장 중 재편집·실패 후 재시도·프로젝트 전환을 검사합니다.
- **내보내기 실패 원인 분류 오류:** 소문자로 바꾼 오류에 대소문자가 섞인 검색어를 비교하던 부분과 불완전 응답 분류를 수정했습니다.
- **중단·정체된 작업의 안내 소실:** 안전하게 재구성한 watchdog 원인·재시도 안내를 유지하고, 외부 공급자 오류 본문은 계속 숨깁니다.
- **오류 안내에 삭제된 공급자·로그인·설정 메뉴가 남아 있음:** 사내 Azure 및 현재 서버 환경변수에 맞춘 한국어·영어 안내로 바꿨습니다.

별도 worktree의 `72c71e0`에서도 관련 프런트엔드 10건, 백엔드 14건의 실패가 재현됐습니다. 따라서 이들을 모두 이번 Azure/Node 버전업이 새로 만든 오류라고 분류하지 않습니다. 회귀 검증을 확대하면서 기존 문제도 함께 수정했습니다.

## 테스트 정리 내역

초기 전체 검사에서는 백엔드 22건, 프런트엔드 17건과 수집 오류 2건이 발생했습니다. 실제 기능 문제와 달라진 요구사항을 구분했습니다.

- 이미 제거된 데스크톱 설정·저장 위치 UI를 import하던 두 테스트 파일은 삭제했습니다. 해당 기능이 웹에서 통과했다고 계산하지 않습니다.
- 제거된 공개 모델 공급자·자동 모델 다운로드를 기대하던 검사는 Azure 전용·외부 자동 다운로드 없음 계약으로 교체했습니다.
- 영어 번역으로 바뀐 픽스처의 길이, 한국어 UI 문구, 의도된 DB 정책 정규화 기대값을 실제 계약에 맞췄습니다.
- 구버전 DB migration 검사는 불완전한 테이블에 revision만 찍던 픽스처 대신 실제 과거 migration으로 스키마를 만든 뒤 프로젝트·템플릿·설정 보존을 검사합니다.
- CI는 선택한 일부 테스트에서 전체 unit/Vitest와 7개 브라우저 시나리오로 확대했습니다. 실제 외부 서비스 키가 필요한 예전 공급자 integration 테스트와 Electron 패키징은 실행 범위에 포함하지 않습니다.

## 남은 확인

사내 Azure 배포 권한·API 버전·모델 품질, 실제 한국어 TTS/OCR 품질, 복잡한 자료의 편집형 PPTX 복원 정확도는 사내 환경에서 확인해야 합니다. 1 vCPU·2GB 제한 및 4명 동시 사용 부하는 이번 결과로 보장하지 않습니다. Sol.A OAuth·사용자 소유권·사용량·외부 DB·영속 큐 통합도 별도 작업입니다.

재현 명령은 [검증 안내](VALIDATION.md), 자동 실행은 [Local Web workflow](../../.github/workflows/local-web.yml)를 참고하세요. 테스트 로그는 로컬 `.runtime/regression/`, 브라우저 산출물은 `frontend/test-results/`에 저장합니다.
